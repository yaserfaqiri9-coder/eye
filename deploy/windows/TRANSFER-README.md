# انتقال دیتابیس محلی با فلش

`build-transfer-snapshot.ps1` از دیتابیس `127.0.0.1:3307/alshifa_dev` این پروژه کپی می‌گیرد.
رمز را از `.tools/dev-secrets.json` می‌خواند و حساب‌های سرور MySQL را صادر نمی‌کند.
فایل‌های `backend/src/AlShifa.Api/storage` و تمام جدول‌های دیتابیس منتقل می‌شوند.
اسکریپت روی دیتابیس مبدأ چیزی نمی‌نویسد و اگر در جریان کپی محتوای آن تغییر کند متوقف می‌شود.

نمونهٔ ساخت کپی، پس از ساخت نسخهٔ جدید با `build-release.ps1` و `build-installer.ps1`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File deploy/windows/build-transfer-snapshot.ps1 -Destination release/AlShifa-USB-NEW/2-Database/Snapshot-Verified
```

هر بار پوشهٔ مقصد تازه انتخاب کنید. `manifest.json` شامل تعداد و checksum جدول‌ها،
نسخهٔ migrationها، خلاصهٔ موجودی و SHA-256 فایل‌ها است. فقط پس از بازیابی موفق در
دیتابیس مستقل با نام تصادفی، نشان `restoreVerified` نوشته می‌شود. نام دیتابیس
آزمایشی از قبل موجود را بازنویسی نمی‌کند و فقط دیتابیس ساخته‌شدهٔ خودش را حذف می‌کند.

کنار پوشهٔ `Snapshot-Verified` این فایل‌ها را کپی کنید:

- `Restore-Database.bat`
- `Restore-Database-Interactive.ps1`
- `restore-transfer.ps1`
- `transfer-common.ps1`
- `common.ps1`

پس از نصب تازه با `Install-AlShifa.exe`، روی میزبان شفاخانه `Restore-Database.bat`
اجرا می‌شود. سرویس و مسیر نصب تطبیق داده می‌شوند؛ دیتابیس مقصد باید `alshifa`
محلی با همان جدول‌ها و migrationها باشد. وجود هر رکورد عملیاتی، انتقال را متوقف می‌کند.
کاربر مشخصات مبدأ را می‌بیند، `TRANSFER` را تایپ می‌کند و نام و رمز مدیر جدید می‌دهد.
وجود AuditLogs فقط زمانی مجاز است که تمام رکوردهایش دقیقاً Login یا LoginFailed
از نوع User باشند؛ هر نوع سابقهٔ دیگر انتقال را متوقف می‌کند. رویدادهای ورود در
کپی قبل از انتقال نگه داشته می‌شوند. جدول‌های کاری همچنان باید خالی باشند.
مبدأ شامل حساب‌ها و رکوردهای فعلی، از جمله هر معلومات آزمایشی باقی‌مانده است.

سرویس هنگام انتقال متوقف است. از مقصد و storage قبل از تغییر کپی گرفته می‌شود؛
پس از واردکردن، تعداد و checksum همهٔ جدول‌ها و hash فایل‌های storage بررسی می‌شود.
سپس مدیر تازه ساخته می‌شود و health برنامه بررسی می‌شود. در صورت شکست، دیتابیس
اولیه از کپی قبل از انتقال بازگردانده می‌شود؛ اگر بازگردانی شکست بخورد، سرویس متوقف می‌ماند.
کپی قبل از انتقال در `<Root>/transfer-backups` برای مراجعهٔ بعدی نگه داشته می‌شود.

## فقط موجودی

`build-stock-snapshot.ps1` فقط دواها و موجودی را صادر می‌کند: محصولات، دسته‌ها، حرکت موجودی
اولیه و ثبت حسابداری همان موجودی اولیه. مریض، مراجعه، فیش، پرداخت، مصرف، صندوق، کاربران
آزمایشی، سابقه و Sync منتقل نمی‌شوند. کاربر 1 فقط به عنوان ثبت‌کنندهٔ موجودی می‌ماند، بدون
رمز، بدون نقش و قفل‌شده. بازیابی با همان `Restore-Database.bat` است.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File deploy/windows/build-stock-snapshot.ps1 -Destination release/AlShifa-USB-NEW/2-Database/Snapshot-Verified
```

## برگرداندن انتقال

اگر انتقال معلومات ناخواسته آورد، `Undo-Transfer.bat` دیتابیس را به کپی ذخیره‌شده پیش از
انتقال در `<Root>/transfer-backups` برمی‌گرداند. پیش از آن، وضع فعلی در `undo-*` نگه
داشته می‌شود. فقط برای نصب تازه‌ای است که هنوز در آن کار نشده است.

این ابزار برای ادغام دو دیتابیس فعال یا جایگزینی معلومات شفاخانهٔ در حال کار نیست.
برای به‌روزرسانی نصب فعال، همان مسیر `update.ps1` با بکاپ و بررسی بازیابی را استفاده کنید.
نصب سرویس، گواهی، LAN، چاپگر و ری‌استارت واقعی باید روی تجهیزات مقصد بررسی شوند.
